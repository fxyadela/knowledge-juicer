# 内容质量处理指南

本文档提供针对不同质量类型输入内容的详细处理策略。

---

## 1. 高质量内容

**识别标志**：
- 逻辑结构清晰，论点有序展开
- 使用准确的术语，定义明确
- 提供充分的例证、数据或代码示例
- 内容完整，覆盖主题的核心方面

**处理策略**：
- 按用户选择的输出模式执行，默认优先生成低认知负荷的速学笔记
- 专注于教育优化：重新组织结构以提高学习效果
- 添加元认知元素（反思提示、自我评估问题）
- 补充跨领域联系，拓宽知识框架
- 识别高级概念，为进阶学习者提供延伸阅读建议

---

## 2. 不完整内容

**识别标志**：
- 话题中途转变，缺乏收尾
- 逐字稿存在明显空白（如 `[inaudible]`、`[...]`）
- 某些概念被提及但未展开说明
- 前提知识未做铺垫

**处理策略**：
1. **标注知识空白**：在笔记中使用 `⚠️ 内容缺失` 标记明确的断裂点
2. **保持连贯性**：通过已有内容进行逻辑推断，用虚线框标注推断内容
3. **补充建议**：在"应用"或"进一步学习"部分建议补充资源，填补空白
4. **降低置信度说明**：在受影响的部分注明"此部分基于有限信息，建议查阅补充资料"

**示例标注格式**：
```
> ⚠️ **内容缺失**：原始材料在此处缺少对 [概念X] 的完整解释。
> 以下内容基于上下文推断，建议参阅 [相关资源] 进行核实。
```

---

## 3. 技术性/复杂内容

**识别标志**：
- 大量专业术语，无日常类比
- 多层嵌套的抽象概念
- 依赖数学公式、代码或图表
- 需要较深的领域先验知识

**处理策略**：
1. **术语表**：在笔记末尾添加"术语速查表"，每个术语给出简洁定义
2. **分层解释**：
   - **基础层**：用生活类比解释核心思想（"就像...一样"）
   - **标准层**：标准的技术定义和用法
   - **高级层**：深入的实现细节或边界情况
3. **可视化**：使用 ASCII 图表、流程图或伪代码辅助说明
4. **代码示例**：将抽象概念转化为可运行的最小示例
5. **递进复杂度**：确保概念图中的层次从基础到高级清晰可见

**分层示例格式**：
```
### [概念名称]

🟢 **简单理解**：[日常类比或直觉解释]

🔵 **标准定义**：[准确的技术定义]

🔴 **深入细节**：[高级实现或边界情况]（可选）
```

## 4. 可能不准确的内容

**识别标志**：
- 与公认知识相矛盾
- 使用模糊或夸大的表述（"总是"、"从不"、"绝对"）
- 引用过时数据或未注明来源的统计数字
- 与已知事实不符的说法

**处理策略**：
1. **标记存疑内容**：使用 `❓ 存疑` 标注需要核实的说法
2. **区分类型**：
   - 🔴 **已知错误**：与既定事实明显矛盾，直接注明正确信息
   - 🟡 **待核实**：无法立即判断的说法，建议用户自行核实
   - 🔵 **演讲者观点**：明确标注为个人观点，而非客观事实
3. **不删除原始内容**：保留原始表述，在旁边添加注释，而非替换
4. **提供核实路径**：在笔记末尾列出用于核实关键说法的推荐资源

**标注格式**：
```
> ❓ **存疑**：演讲者称"[原始说法]"。
> 根据 [可靠来源]，实际情况是 [正确信息]。建议核实。
```

## 平台特定质量注意事项

### YouTube 逐字稿
- 自动生成的字幕可能存在同音词错误（如 "there/their"、技术术语拼写错误）
- 时间戳跳跃可能意味着有剪辑，注意内容连贯性
- 章节标记（如果有）有助于识别内容结构

### X (Twitter) 推文串
- 推文字数限制导致观点碎片化，需要整合上下文
- 回复链可能包含重要的补充或纠错信息
- 引用推文（quote tweets）可能包含关键背景

### Reddit 讨论
- 主帖质量参差，高赞评论往往包含更可靠的补充信息
- 区分 OP（原帖作者）观点和社区共识
- 注意帖子发布日期，技术内容可能已过时

### 博客文章
- 检查发布日期，评估时效性
- 区分教程（操作性）和观点文章（主观性）
- 注意作者背景和文章的潜在立场
